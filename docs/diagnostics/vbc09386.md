# VBC09386: Name conflicts with existing module, project, or object library

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (static semantics / abstract syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBCompileErrorInfo`](https://rubberduck-vba.github.io/RDCore.SDK/api/RDCore.SDK.Model.Errors.VBCompileErrorInfo.html)

A module is named as a library or a project that its project references.

A module's name is the one its `Attribute VB_Name` line says, or its file's name when it has none. It cannot be the name of a project that the module's
project references (**MS-VBAL §4.2**). A referenced library is such a project, and so is the standard library, `VBA`, which every project references
([**MS-VBAL §4.1** Projects](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/4cd406c7-1ade-4522-8d7b-933183059ac7)).
Case does not matter: `excel` is the name of the `Excel` library. MS-VBA refuses to rename a module to such a name, with the message "Name conflicts with
existing module, project, or object library", and gives a module it imports with such a name another one (`Excel1`). The module does not load, and a
program that has it does not run.

The name of a library the project does not reference is a name like any other. A module named as its own project keeps the name, as a project file can
give it.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A module is named as the standard library.|`Attribute VB_Name = "VBA"`|Give the module another name, such as `VBAHelpers`.|
|A module is named as a library the project references.|`Attribute VB_Name = "Excel"`, in a project that references `Excel`|Give the module another name, such as `ExcelTools`.|
|A module is named as a project the project references.|`Attribute VB_Name = "NavalLib"`, in a project that references the project `NavalLib`|Give the module another name, or the project.|
