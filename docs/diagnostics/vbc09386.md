# VBC09386: Name conflicts with existing module, project, or object library

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (static semantics / abstract syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBCompileErrorInfo`](https://rubberduck-vba.github.io/RDCore.SDK/api/RDCore.SDK.Model.Errors.VBCompileErrorInfo.html)

A module is named as another module of its project, or as a library or a project that its project references.

A module's name is the one its `Attribute VB_Name` line says, or its file's name when it has none. Every module of a project has a name of its own
(**MS-VBAL §4.2**). Of two or more modules with one name, none loads and each is reported, where it says its name or, when its file names it, at its
start. The program is invalid and does not run. Case does not matter: `Helpers` and `HELPERS` are one name. MS-VBA refuses to rename a module to
the name of another, with this message, and gives a module it imports with such a name another one (`Helpers1`).

A `Partial` block is a part of the module of its name, not a module of its own
([**RD-VBAL §5.1**](../specs/rd-vbal.5.1.module-body-structure.md#modules-of-parts)): a module has one part without `Partial` at most, and one file
holds one part of a module at most.

A module's name cannot be the name of a project that the module's project references either (**MS-VBAL §4.2**). A referenced library is such a
project, and so is the standard library, `VBA`, which every project references
([**MS-VBAL §4.1** Projects](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/4cd406c7-1ade-4522-8d7b-933183059ac7)).
Case does not matter: `excel` is the name of the `Excel` library. MS-VBA refuses to rename a module to such a name, with the message "Name conflicts with
existing module, project, or object library", and gives a module it imports with such a name another one (`Excel1`). The module does not load, and a
program that has it does not run.

The name of a library the project does not reference is a name like any other.

**RD-VBA differs from MS-VBA:** a module named as its own project keeps the name. **MS-VBAL §4.2** excludes the name of the module's own project too,
and MS-VBA refuses it.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|Two files say one name.|`Attribute VB_Name = "Helpers"` in `Helpers.bas` and in `Tools.bas`|Give one of the modules another name.|
|A file says no name, and another module says its file's.|`Helpers.bas` with none, `Tools.bas` with `VB_Name = "Helpers"`|Give one of the modules another name.|
|A block without `Partial` has the name of another module.|`Module Helpers` in `Tools.bas`, and `Helpers.bas`|Give the block another name, or write `Partial` in its header to make it a part of `Helpers`.|
|One file has two parts of a module.|`Partial Module Helpers` twice in `Tools.bas`|Write the code of both blocks in one.|
|A module is named as the standard library.|`Attribute VB_Name = "VBA"`|Give the module another name, such as `VBAHelpers`.|
|A module is named as a library the project references.|`Attribute VB_Name = "Excel"`, in a project that references `Excel`|Give the module another name, such as `ExcelTools`.|
|A module is named as a project the project references.|`Attribute VB_Name = "NavalLib"`, in a project that references the project `NavalLib`|Give the module another name, or the project.|
