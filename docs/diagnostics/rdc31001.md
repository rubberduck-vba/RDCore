# RDC31001: Circular reference of projects

**Severity:** Error &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core, the workspace and its project files) &nbsp;·&nbsp;
**Raised by:** the language server, on the `.rdproj` of each project on the cycle, as the workspace loads and each time it is loaded again

A project can reference another project of the workspace, and use its public modules, classes and procedures. It cannot reference itself, or a project that
references it, directly or through other projects: VBA refuses such a reference, as no project would then come first. The message gives the path of the
cycle, from the project that comes first in the workspace back to it, as `NavalLib → NavalWindow → NavalLib`. Each project on the path is reported, on its
own `.rdproj`.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|Two projects reference each other.|`NavalLib` references `NavalWindow`, and `NavalWindow` references `NavalLib`.|Remove one of the two references. What both projects need usually belongs in the one the other references.|
|A project references itself through other projects.|`A` references `B`, `B` references `C`, and `C` references `A`.|Remove one of the references on the path.|
|A project references itself.|The references of `NavalLib` name `NavalLib`.|Remove the reference.|

A reference to a library, or to a name that no project of the workspace has, is on no cycle.
