# RDC00417: Folder annotation not the file's folder

**Severity:** Information &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `FolderAnnotationAnalyzer`

A `'@Folder` annotation names a folder other than the one the module's file is in, under the root of its project.

RD-VBA reads a module's folder from where its file is, and `'@Folder` changes nothing. Rubberduck's Code Explorer in MS-VBA shows a module in the folder
its `'@Folder` names. When the annotation names the file's own folder, the Code Explorer shows the folders of the workspace once the project is imported
into MS-VBA.

The folder is written as the folders from the project's root to the file, joined with a `.`: the file `Parent/Child/Module1.bas` is in
`"Parent.Child"`. A file at the root of the project is in no folder. Names are compared as they are written, case included.

A module with no `'@Folder` is not reported. Nor is a file under a folder whose name has a `.` in it, which the annotation would read as two folders.

The finding is the annotation.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|The annotation names another folder.|`'@Folder("Other")` in `Parent/Child/Module1.bas`|Write `'@Folder("Parent.Child")`.|
|The annotation names a folder for a file at the root.|`'@Folder("Parent")` in `Module1.bas`|Remove the annotation.|

## Quick fix

The diagnostic comes with a quick fix. *Write '@Folder("Parent.Child")* replaces the annotation's argument with the file's folder. At the root,
*Remove '@Folder* removes the annotation, and its line when nothing else is written in the comment.
