# RDC00416: Module annotation has a short form

**Severity:** Information &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `ModuleAnnotationShortFormAnalyzer`

A block of a file (`Class Name ... End Class`, `Module Name ... End Module`) declares a module, and a module annotation of that module is written in its
long form: `'@ModuleDescription` or `'@IgnoreModule`.

The comment lines directly above a block's header annotate the block's module. There, `'@Description` describes the module and `'@Ignore` suppresses
diagnostics in it, so the long forms are not needed. They still work in the block's declarations section, as they do in a module of its own file.

Only a document that allows file-level statements has blocks. A module of its own file is not reported: it has no header to write the short form above.

The finding is the annotation.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A module annotation is in the block's declarations section.|`'@ModuleDescription("Shapes")` on the line after `Class Shape`|Write `'@Description("Shapes")` above `Class Shape`.|
|A module annotation is above the header, in its long form.|`'@IgnoreModule RDC01001` above `Class Shape`|Write `'@Ignore RDC01001`.|

## Quick fix

The diagnostic comes with a quick fix. *Write '@Description above the header* (or *'@Ignore*) writes the annotation, with its arguments, on a line of its
own above the block's header, and removes it from the block. Its line goes with it when nothing else is written in the comment. Above the header, the fix
renames the annotation.
