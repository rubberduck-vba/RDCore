# RDC00302 — Obsolete Call statement

**Severity:** Hint &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** [`ObsoleteCallStatementAnalyzer`](../api/RDCore.Diagnostics.Analyzers.ObsoleteCallStatementAnalyzer.html)

A procedure is called with a `Call` statement written with the `Call` keyword.

The call is the same without the keyword: `Call Work(1)` and `Work 1` invoke the same procedure the same way
([**MS-VBAL §5.4.2.1** Call Statement](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/f7c864a8-8fce-49dc-8347-30dc749d6576)).
The keyword is a relic of an older syntax; the diagnostic is an opinion of the analyzer and not a condition of the language.

That the callee of a statement is written with the keyword is a **fact** of the expression
([`ValueExpressionSemanticFlags.ExplicitCallKeyword`](../api/RDCore.SDK.Semantics.Flags.ValueExpressionSemanticFlags.html)): the analyzer reads
it off the facts the environment host found, and is not given the syntax tree to look it up in.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A call statement is written with `Call`.|`Call Work(1)`|Write it without the keyword: `Work 1`.|
