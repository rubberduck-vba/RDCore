# RDC11051: Set to an incompatible class

**Severity:** Warning &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `SetToAnIncompatibleClassAnalyzer`

A `Set` statement assigns a target declared as a class a value declared as another class, and no object of the value's class can be an object of
the target's.

A variable declared as a class holds an object of that class, or of a class that implements it. `Set` takes an object of the target's class, or of a
class that implements it, and raises run-time error 13 (Type mismatch) for any other. When neither class implements the other and no class of the
workspace implements both, every object the value can hold is refused. VBA compiles the statement, and raises error 13 every time it runs with an
object.

```vb
Dim shape As IShape
Dim item As Account          ' Account does not implement IShape
Set item = New Account
Set shape = item             ' error 13
```

This is what Microsoft Office VBA does, as [**MS-VBAL §5.5.2.2.1**][set-coercion] states it. These are not reported:

- a value of an interface that the target's class implements (`Set circle = shape`), which holds an object of the target's class when the code runs;
- a value of an interface that another class implements along with the target's;
- `Nothing`, and a target declared `Object` or `Variant`;
- an object of a library's class, which answers for itself when the code runs.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|The class is meant to be usable as the interface.|`Set shape = item`|Add `Implements IShape` to the class `Account`.|
|The wrong variable is assigned.|`Set shape = item`|Assign an object of a class that implements `IShape`.|
