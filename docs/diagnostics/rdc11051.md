# RDC11051: Member not on the declared interface

**Severity:** Warning &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `MemberNotOnDeclaredInterfaceAnalyzer`

A member is accessed on an object declared as a class of a referenced library, and the class does not declare it.

A library's class is extensible: the host can add members to its objects that the library does not declare. MS-VBA compiles the access, and looks the
member up on the object when the code runs
([**MS-VBAL §5.6.12** Member Access Expressions](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/af3a4059-3059-4e79-8aa5-685324fb266a)).
If the object has no such member, the access raises run-time error 438 (Object doesn't support this property or method). A misspelled name compiles
the same way, and fails only when the line runs.

The finding is the member access.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A member that a host's class does not declare.|`Dim ws As Worksheet` / `ws.Rnage("A1").Value = 1`|Correct the name (`ws.Range`).|
|A member that a `UserForm` does not declare.|`Dim f As UserForm` / `f.MyProp = 1`|Declare the variable as the form's own class (`Dim f As UserForm1`), whose members are known, or correct the name.|
|A member the host adds to its objects.|`adoConnection.SomeStoredProcedure 42` of an ADO `Connection`|Use a member the class declares where there is one (an ADO `Command` for a stored procedure).|

## Notes

A member that a class of the VBA library (`Collection`) does not declare is [RDC11010](rdc11010.md): an object of such a class has no other
members, and the access raises 438 every time it runs.

An access on an `Object` or a `Variant`, on a class module of the workspace (`VB_Extensible` or not), or on a control of a form is not reported. A
control's object is wrapped in its extender, which adds members its class does not declare (`Left`, `Visible`).
