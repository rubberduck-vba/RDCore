# VBC09320 — Inconsistent property accessors

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (static semantics / abstract syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBCompileErrorInfo`](../api/RDCore.SDK.Model.Errors.VBCompileErrorInfo.html)

A module's `Property Get`, `Property Let`, and `Property Set` sharing a name do not together describe one
valid property (**MS-VBAL §5.3.1.7**). Raised where the accessors are resolved as a group, by
[`ScopeTreeSymbolResolver`](../api/RDCore.SDK.Model.Symbols.ScopeTreeSymbolResolver.html), the moment more
than one accessor exists and any of the conditions below holds.

The verbose detail lists the colliding accessor declarations.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|Two accessors' index-parameter lists differ in count, name, declared type, or `ByRef`/`ByVal` mechanism.|`Property Get Foo(i As Integer)` next to `Property Let Foo(j As Long, v As Integer)`|Give every accessor of the property the exact same index parameters.|
|An index parameter is `Optional` or a `ParamArray`, and the property has more than one accessor.|`Property Get Foo(Optional i As Integer)` next to `Property Let Foo(i As Integer, v As Integer)`|Either drop `Optional`/`ParamArray` from the index, or make the property `Get`-only.|
|`Property Let` and `Property Get` sharing a name declare a different value type.|`Property Get Foo() As Long` next to `Property Let Foo(v As String)`|Give the `Let` accessor's value parameter the same declared type as the `Get` accessor's return type.|
|`Property Set`'s value parameter is not `Object`, `Variant`, or a named class.|`Property Set Foo(v As Long)`|Type the value parameter `Object`, `Variant`, or a class.|

## Notes

Implicit vs. explicit `ByRef` on a corresponding index parameter is not a difference — only the actual
`ByRef`-vs-`ByVal` mechanism is compared, matching **MS-VBAL §5.3.1.7**'s own exception for that case. A
single accessor (a `Get`-only or `Let`-only property) has nothing to be inconsistent with, and is never
reported by this code — `Optional`/`ParamArray` index parameters are only ever legal there.

The real VBE bundles all of these conditions into one compile error: *"Definitions of property procedures
for the same property are inconsistent, or property procedure has an optional parameter, a ParamArray, or
an invalid Set final parameter."* The index-parameter-equivalence and `Property Set` value-type conditions
are literal MS-VBAL static-semantics bullets; the `Optional`/`ParamArray`-implies-`Get`-only consequence is
not spelled out verbatim in the spec text, but is confirmed by the compiler's own error wording.
