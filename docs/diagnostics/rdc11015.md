# RDC11015 — Object with no default member used as a value

**Severity:** Warning &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** [`ValueOfObjectWithNoDefaultMemberAnalyzer`](../api/RDCore.Diagnostics.Analyzers.ValueOfObjectWithNoDefaultMemberAnalyzer.html)

An object of a class that has no default member is where a value is expected: assigned with `Let` to a variable of a value type or to a `Variant`, an
operand of an operator other than `Is`, or an argument of a parameter declared with a value type (`ByVal x As Long`, `CInt`, the `Limit` of `Split`).

The object has no value to give. VBA compiles the code, and raises a run-time error when it runs:

- error 438 (Object doesn't support this property or method) when the variable holds an object;
- error 91 (Object variable or With block variable not set) when it holds `Nothing`.

So, with `o` declared `As Plain`, a class with no default member, `c = o`, `c = CInt(o)` and `Split("a,b,c", ",", o)` all raise one of those errors,
every time they run.

This is what Microsoft Office VBA does. The language specification says otherwise:
[**MS-VBAL §5.5.1.1**](../specs/rd-vbal.5.5.1.1.static-semantics.md) makes a class with no accessible default member invalid to Let-coerce, which is a
compile error (Type mismatch). RD-VBA runs the code as VBA does, and this warning stands in for that compile error.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A member of the object is meant.|`n = widget`, meaning its count|Read the member: `n = widget.Count`.|
|The object itself is meant, kept in a `Variant`.|`v = widget`|`Set` it: `Set v = widget`.|
|The object is compared with another object.|`If a = b Then`|Compare the references: `If a Is b Then`.|
