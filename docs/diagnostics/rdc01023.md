# RDC01023: Parameter can be passed by value

**Severity:** Information &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `ParameterCanBeByValAnalyzer`

A parameter is passed by reference, and its procedure neither assigns it nor passes it to a procedure that may assign it.

A parameter declared `ByRef`, or with neither `ByRef` nor `ByVal`, gives the procedure the caller's variable
([**MS-VBAL §5.3.1.5** Parameter Lists](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/78bcb344-4966-4401-bb55-72729790ebee)).
A procedure that never changes it does the same with `ByVal`, and its signature then says that the caller's variable does not change.

Not reported:

- an array, a `ParamArray` and a user-defined type, which are passed by reference only;
- the value parameter of a `Property Let` or `Property Set`, which is passed by value whatever it states;
- a parameter of an implementation of an interface member, of a handler of an event, and of a `Declare`, whose signature is another's.

> [!NOTE]
> **Not implemented.** A parameter of an interface member or of an event is not reported, even when no implementation and no handler assigns its own.

The finding is the name of the parameter. The quick fix writes `ByVal` in place of `ByRef`, or before the name.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A parameter passed by reference is only read.|`Sub Show(count As Long)`<br>`    Debug.Print count`<br>`End Sub`|Pass it by value: `Sub Show(ByVal count As Long)`.|
