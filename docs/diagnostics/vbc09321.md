# VBC09321 — Argument required for Property Let or Property Set

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (static semantics / abstract syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBCompileErrorInfo`](../api/RDCore.SDK.Model.Errors.VBCompileErrorInfo.html)

A `Property Let` or `Property Set` declares no parameters at all, so it has no value parameter to receive
what is being assigned. **MS-VBAL §5.3.1.5**: `property-parameters = "(" [parameter-list ","] value-param
")"` — `value-param` is never bracketed, so it is always mandatory, index parameters or not. Raised by
[`ScopeTreeSymbolResolver`](../api/RDCore.SDK.Model.Symbols.ScopeTreeSymbolResolver.html), ahead of and
instead of [VBC09320](vbc09320.md), the moment a name resolves to a `Property Let`/`Set` with an empty
parameter list — a lone accessor is checked exactly the same as one paired with a `Get`.

The verbose detail lists the offending accessor declaration.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A `Property Let` with no parameters.|`Property Let Foo()`|Add the value parameter: `Property Let Foo(value As Long)`.|
|A `Property Set` with no parameters.|`Property Set Foo()`|Add the value parameter: `Property Set Foo(value As Object)`.|
|A `Property Let`/`Set` with no parameters, paired with a valid `Get`.|`Property Get Foo() As Long` next to `Property Let Foo()`|Same fix — the missing value parameter is reported even though the `Get` accessor is otherwise fine.|

## Notes

A `Property Get` needs no value parameter — it has no value being assigned to it, only (optionally) index
parameters to read by — so this code never applies to one. Compare
[VBC09320](vbc09320.md), which needs at least two accessors present to say anything about their index
parameters or value types; this code fires for a single accessor too, since a `Property Let`/`Set` with an
empty parameter list is invalid on its own, independent of whether it collides with anything else.
