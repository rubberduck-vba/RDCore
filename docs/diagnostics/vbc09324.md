# VBC09324 — Invalid type for WithEvents variable

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (static semantics / abstract syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBCompileErrorInfo`](../api/RDCore.SDK.Model.Errors.VBCompileErrorInfo.html)

A `WithEvents` variable is declared as a type that cannot raise events to it.

[**MS-VBAL §5.2.3.1.2** WithEvents Variable Declarations](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/f41f8ec5-7a2d-4797-8ba9-0e3b52113b9e)
requires the declared type to be a specific class that has at least one event member, and not the class defined by the class
module that contains the declaration.

This code is raised by
[`ClassModuleEventSemantics`](../api/RDCore.SDK.Semantics.Static.ClassModuleEventSemantics.html). The verbose detail names
the variable, the type, and which of the rules it breaks.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|The type is not a specific class.|`Private WithEvents Src As Object`, or `As Long`|Declare the variable as the class that raises the events: `Private WithEvents Src As Source`.|
|The class has no events.|`Private WithEvents Src As Silent`, where `Silent` declares none|Declare an event in the class, or handle nothing: remove `WithEvents`.|
|The type is the class of the module containing the declaration.|`Private WithEvents Me2 As Sink`, in the class module `Sink`|A class cannot handle its own events through a variable. Raise them with `RaiseEvent` and handle them in another class.|

## Notes

A type that is not resolved is not reported: it is not known to be wrong. Declaring a type that does not exist is reported
where types are resolved.
