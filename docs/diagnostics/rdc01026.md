# RDC01026: Code left out by conditional compilation

**Severity:** Hint &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** the language server, from the branches of each `#If` block that the constants of the module and of the project leave out

A branch of a `#If` block is the code between one of its directives (`#If`, `#ElseIf`, `#Else`) and the next one. With the constants as they are, one
branch of the block at most is compiled, and the others are not part of the module: nothing in them runs, and nothing they declare exists.

The finding covers each branch that is left out, from its first line to its last. The directive lines are not part of it, and a `#If` block written inside
a branch that is left out is left out with it. An editor shows the lines faded, as it shows code that is never reached. The finding is not a problem to fix:
it changes as the constants do, when a `#Const` of the module or a constant of the project is changed.

A branch whose condition cannot be evaluated is not reported, nor is a branch with no lines.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A condition that is false.|`#If DEBUGMODE Then`, with `#Const DEBUGMODE = 0`|None needed. Change the constant to compile the branch.|
|A branch after the one that is compiled.|`#Else`, after a `#If Win64 Then` on a 64-bit platform|None needed.|
|A block inside a branch that is left out.|`#If VBA7 Then` inside a `#If Mac Then` branch, on Windows|None needed. The whole outer branch is reported once.|
