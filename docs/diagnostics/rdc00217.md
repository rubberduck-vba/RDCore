# RDC00217: Function result always discarded

**Severity:** Information &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `FunctionReturnValueAlwaysDiscardedAnalyzer`

A `Function` is called only as a statement: every call in the project discards the value it returns.

A call statement can call a `Function` as well as a `Sub`
([**MS-VBAL §5.4.2.1** Call Statement](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/f7c864a8-8fce-49dc-8347-30dc749d6576)).
When no caller uses the value, the function works as a `Sub`, and the code that assigns its return value can be removed.

A function is reported when its calls are all in the project, which the analysis counts:

- a `Private` function, which only its module calls;
- a `Friend` function;
- a `Public` function of a program, a project that starts at its entry point (the procedure its `.rdproj` names, or its `Sub Main`;
  see [RDC30001](rdc30001.md)) and is not a library.

A `Public` function of a library, or of a project with no entry point, can be called by another project or by the host that runs it, and is not reported.
Nor is a function of a class that an access bound late names (`o.Save`, with `o` declared `As Object`) or that a `CallByName` names with a string literal,
nor any function of a class when the program calls `CallByName` with any other name. A `Private` function is not reported when a string of the
project writes its name, or when its module calls `CallByName` with a name that is not a string literal: the call can name it when the code runs. Nor is
one that implements a member of an interface (`Private Function IShape_Area() As Double`), which a call through the interface runs. A function that no
code calls, or that only calls itself, is reported as [RDC01025](rdc01025.md) instead.

The finding is the declaration of the function. Each call is also reported as [`RDC00216`](rdc00216.md).

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|No caller needs the value.|`Friend Function Add(ByVal n As Long) As Long`, called only as `c.Add 1`|Make it a `Sub`.|
|A caller should have checked the value.|`Friend Function Save() As Boolean`, called only as `doc.Save`|Use the value where it matters: `If Not doc.Save Then ...`.|
|A `Public` function of a program whose callers all discard the value.|`Public Function Note(ByVal s As String) As Boolean`, called only as `Note "x"`|Make it a `Sub`, or use the value where it matters.|

## Quick fix

The diagnostic comes with a quick fix, *Make '…' a Sub*. It writes `Sub` for `Function`, `End Sub` for `End Function` and `Exit Sub` for each
`Exit Function`, removes the `As` clause, and removes each statement that assigns the return value. The calls are left as they are: a call statement calls a
`Sub` as it calls a `Function`, and the program does what it did.

The quick fix is offered when every assignment of the return value is on lines of its own, given a literal or the value of a variable, and the function
names its return value nowhere else. It is not offered for a value that calls a procedure (`Add = Total()`), whose call would be lost, for a `Let` given a
variable of a class, `Object` or `Variant`, whose default member the `Let` may call, nor for a function written with a type character (`Function Add&()`).
