# RDC00220: ParamArray ignores Option Base

**Severity:** Hint &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `ParamArrayOptionBaseAnalyzer`

A `ParamArray` parameter is declared in a module that states `Option Base 1`.

`Option Base 1` makes 1 the lower bound of the module's arrays declared without one
([**RD-VBAL §5.2.1** Option Directives](../specs/rd-vbal.5.2.1.option-directives.md)). Each call of the procedure makes its param array a new array
of `Variant` with a lower bound of 0, whatever the `Option Base`
([**RD-VBAL §5.3.1.11** Procedure Invocation Argument Processing](../specs/rd-vbal.5.3.1.11.procedure-invocation-argument-processing.md#paramarray)).
Code that reads the param array from index 1 misses its first argument.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A `ParamArray` parameter in a module with `Option Base 1`.|`Option Base 1` … `Sub Log(ParamArray values())`|Loop from `LBound(values)` to `UBound(values)`.|
