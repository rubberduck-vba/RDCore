# VBC00062: Invalid in a Class or Module block

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (parser / concrete syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBSyntaxErrorInfo`](https://rubberduck-vba.github.io/RDCore.SDK/api/RDCore.SDK.Model.Errors.VBSyntaxErrorInfo.html)

A line that only a module file has is written inside a `Class` or `Module` block: an `Attribute` line, the `VERSION` line, a
`BEGIN` ... `END` header, or `Option Private Module`.

A block's header states what these lines state in a module file: its name, its kind, and whether other projects see it
(`Public Creatable Class Account`, `Private Module Helpers`). So a block has no file header and no attributes.

This code is raised by the parser, at each such line. The block is read all the same. The same lines outside every block belong to the file's own
module, and are valid there.

As with any syntax error, no code in the project runs while a module has this error
([**RD-VBAL §2.6.1**](../specs/rd-vbal.2.6.1.syntax-errors.md#a-module-with-a-syntax-error)).

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|The module's name.|`Attribute VB_Name = "Account"`|Delete the line: the header names the module.|
|An attribute a header states.|`Attribute VB_Exposed = True`, `Attribute VB_Creatable = True`|Write `Public` or `Creatable` in the block's header (`Public Creatable Class Account`).|
|A private standard module.|`Option Private Module`|Write `Private` in the block's header (`Private Module Helpers`).|
|A class file's header.|`VERSION 1.0 CLASS`, `BEGIN` ... `END`|Delete the lines: the block's header states that the module is a class.|
|Another attribute, of the module or of a member.|`Attribute VB_PredeclaredId = True`, `Attribute Deposit.VB_Description = "Adds."`|Move the module to a file of its own.|

> [!NOTE]
> **Not implemented.** The parse reads what a block's header states (`Public`, `Private`, `Creatable`, `Partial`), and nothing applies it to the
> module. No annotation states a block's other attributes.
