# VBC09331 — Sub or Function not defined

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (static semantics / abstract syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBCompileErrorInfo`](../api/RDCore.SDK.Model.Errors.VBCompileErrorInfo.html)

The code uses a statement, or calls a procedure, that the language it is written in does not have - or that the platform does not accept in it yet.

MS-VBA reports the same error for a call of a name that nothing declares:
[Sub or Function not defined](https://learn.microsoft.com/office/vba/language/reference/user-interface-help/sub-or-function-not-defined).
Which statements exist at all is the language's to say ([`SupportedLanguage`](../api/RDCore.SDK.Workspace.SupportedLanguage.html)), and the
platform's languages do not all have the same ones.

This code is raised by instruction-list lowering
([`InstructionListLowering`](../api/RDCore.SDK.Semantics.Instructions.InstructionListLowering.html)), which is told the language the body is
written in (`InstructionLoweringOptions.Language`). A body lowered for no language is lowered as written. The verbose detail names the statement.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A `Print` with no file number, in a language that does not have such a statement (for now).|`Print "x"`, in RD-VBA or VB6|Print to a file number (`Print #1, "x"`) or to the `Immediate` window (`Debug.Print "x"`). A bare `Print` is a statement of the platform's BASIC.|

## Notes

In VB6 a bare `Print` is the `Print` member of the form or report it is written in. The platform has no forms yet, so it is not a statement of VB6 either.

In VBA `Print` is a reserved word, and the Immediate window accepts a bare `Print` as it does `Debug.Print`. What module code makes of it is not settled, so the
platform does not accept it there for now: this is not a finding that VBA has no such statement, and the rule may change once the behaviour is deciphered.
