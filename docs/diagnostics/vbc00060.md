# VBC00060 — Expression nested too deeply

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (parser / concrete syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBSyntaxErrorInfo`](../api/RDCore.SDK.Model.Errors.VBSyntaxErrorInfo.html)

An expression is nested in more than 2,500 other expressions.

An expression is nested in another when it is part of it: the operand of an operator, an expression in parentheses, the argument of a call. In
`x = (((1)))`, the `1` is nested in three expressions. In `x = 1 + 2 + 3`, the `1` is nested in two additions, because `1 + 2` is the left operand of
`(1 + 2) + 3`. A chain of 2,501 terms joined by `+` is as deep as RD-VBA reads: its first term is nested in 2,500 additions.

Passing an argument by name (`a:=`) or `ByVal` nests it in nothing more than the call. Neither does printing it: `Debug.Print`, `Spc` and `Tab` are not
calls, and what they print is as deep as it is in `x =`.

MS-VBA reports no error for an expression this deep. Excel runs a chain of 2,500 terms, 2,000 nested parentheses and 1,000 nested calls. Given a chain of
3,000 terms, it stops responding and closes, with no dialog (recorded in Excel). RD-VBA reports this error instead, at the expression that passes the limit.

This code is raised by the parser, once for each expression of a statement that passes the limit.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A long chain of operators.|`total = a1 + a2 + a3 + ... + a2600`|Add the terms a few hundred at a time, into a variable.|
|Deeply nested parentheses or calls.|`x = Abs(Abs(Abs( ... Abs(n) ... )))`, 2,600 deep|Compute the inner part first, and assign it to a variable.|

Code generated by a tool is the usual source of an expression this deep. Writing part of it to a variable first gives the same result, and the code runs in
MS-VBA too.
