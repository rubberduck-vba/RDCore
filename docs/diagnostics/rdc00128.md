# RDC00128: Undeclared variable

**Severity:** Warning &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `UndeclaredVariableAnalyzer`

A variable that no statement declares.

In a module with no `Option Explicit`, a name that matches nothing (no variable, constant or procedure of the procedure, the module, another module or a library)
declares a local variable of that name, where the procedure first uses it (**MS-VBAL §5.6.10**). A misspelled name is one of them: `totl = 5` declares `totl`,
and `total` is left as it was. [RDC00101](rdc00101.md) reports the module once; this reports each variable, where it is first used. Such a variable is
legal VBA: the diagnostic is an opinion of the analyzer.

Under `Option Explicit` the same name is a compile error instead, and this is not reported. A `ReDim` that declares its array is [RDC00114](rdc00114.md).

## Fixing it

The code action declares the variable with a `Dim` before the first statement of its procedure, of the type it already has: the type of the character its
first use is written with (`totl$` is a `String`), or else of the `Def<Type>` directive that covers its name, or else `Variant`. The program does what it
did: a local exists from the start of its procedure, wherever it is declared. It is not offered when the procedure's first statement is on the line of
its `Sub`, `Function` or `Property` (`Sub Main(): totl = 1`). A misspelled name is better corrected than declared, and only the user can
tell which it is.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A name that matches nothing, in a module with no `Option Explicit`.|`totl = 5` / `Debug.Print total`: `totl` and `total` are each reported.|Declare the variable (`Dim total As Long`), or correct the name; then add `Option Explicit`.|
