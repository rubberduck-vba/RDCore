# RDC30002: More than one entry point

**Severity:** Error &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core, the builder) &nbsp;·&nbsp;
**Raised by:** `rdc run` and `rdc build`, before the program runs or is written

More than one entry point answers, and the build section of the `.rdproj` does not say which one the program starts at: more than one standard module
declares a `Sub Main`, or is a script, or the name the build section gives is both a script's module and a procedure's. The modules are named on standard
error, with this code. `rdc run` exits with code `2`, and `rdc build` writes no program.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|Two standard modules each declare a `Sub Main`, and the build section names no entry point.|`Program.bas` and `Tools.bas` both have a `Public Sub Main()`|Name the one to start at in the build section (`"entryPoint": "Program.Main"`), rename the other, or run the module's file (`rdc run Program.bas`).|
|Two modules are scripts, and the build section names no entry point.|`Backup.vbs` and `Restore.vbs`|Run the script's file (`rdc run Backup.vbs`), or name its module in the build section (`"entryPoint": "Backup"`).|
|The name the build section gives is a script's module and a procedure too.|`"entryPoint": "Backup"`, with `Backup.vbs` and a `Tools.Backup` procedure|Name the procedure as `Module.Procedure` (`"entryPoint": "Tools.Backup"`), or run the script's file (`rdc run Backup.vbs`).|
