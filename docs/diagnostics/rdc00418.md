# RDC00418: Ignore annotation names no diagnostic

**Severity:** Warning &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** the language server

An argument of `'@Ignore` or `'@IgnoreModule` suppresses nothing. It is not a diagnostic code or the name of a legacy Rubberduck inspection that a code
took the place of, or it names a language error.

`'@Ignore` and `'@IgnoreModule` are deprecated: settings turn a diagnostic off ([Disabling a Diagnostic](../disabling-diagnostics.md)). They are kept
to suppress the diagnostics they name in the source, in the scope that
[**RD-VBAL §2.6.4** Suppression](../specs/rd-vbal.2.6.4.rubberduck-core-diagnostics.md#suppression) gives: the whole file, for a file of one module. Each
argument is a code (`RDC01025`) or the name of a legacy Rubberduck inspection without its `Inspection` suffix (`ProcedureNotUsed`). A language
error (`VBC`, `VBR`, `VBA`) is always reported: the code does not compile, or stops when it runs.

The finding is the argument. The annotation's other arguments still suppress what they name.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|The argument is misspelled.|`'@Ignore ProcedureNotUsd`|Correct it: `'@Ignore ProcedureNotUsed`.|
|The legacy inspection has no counterpart.|`'@Ignore UnrecognizedAnnotation`|Remove the argument.|
|The argument names a language error.|`'@Ignore VBC09302`|Correct the code. A language error cannot be suppressed.|
