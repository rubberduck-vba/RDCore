# RDC00101 — Implicit declarations enabled

**Severity:** Warning &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** [`OptionExplicitAnalyzer`](../api/RDCore.Diagnostics.Analyzers.OptionExplicitAnalyzer.html)

A module does not state `Option Explicit`.

Without it, a name that is not declared is not an error: a variable comes into being where it is used
([**MS-VBAL §5.2.1.3** Option Explicit Directive](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/e9253cf2-5139-4abd-8c1d-eaf390805cb8)),
so a misspelled name goes unnoticed and the program runs with a variable that nothing ever assigns. The diagnostic is an opinion
of the analyzer and not a condition of the language: both are legal VBA.

Whether the module states `Option Explicit` is a **fact** the environment host vouches for
([`ModuleSemanticModel.OptionExplicit`](../api/RDCore.SDK.Semantics.ModuleSemanticModel.html)); the analyzer has nothing to say about a module the host
has not analyzed, and does not guess from the syntax tree.

## How it is raised

|Situation|Resolution|
|---|---|
|The module has no `Option Explicit` directive.|Add `Option Explicit` at the top of the module, and declare what it then reports.|
