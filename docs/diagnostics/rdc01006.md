# RDC01006 — Unsupported document module

**Severity:** Error &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** [`DocumentModuleHostAnalyzer`](../api/RDCore.Diagnostics.Analyzers.DocumentModuleHostAnalyzer.html)

A module is the code of a host application's document, and RD-VBA does not know what that document is: the members and the events of its host's class are
not known, and none of them is a name of the module's code.

What a document module is, the project file says (`Super`, [**RD-VBAL §2.2.3.3.1**](../specs/rd-vbal.2.2.3.projectfile.md#22331-docclasstype-enum)), and
nothing else does: not the module's name, not the extension of its file, not the names of its procedures.

## How it is raised

|Situation|Resolution|
|---|---|
|The project gives the module a `Super` RD-VBA does not support: `Unknown`, or a name of no host it knows.|Give it the document it is: `ExcelWorkbook`, `ExcelWorksheet`, `WordDocument`, `AccessForm` or `AccessReport`.|
|A `.doccls` file (a document module legacy Rubberduck exported) that the project gives no `Super`.|Give it its `Super`. Until then it is read as the module its text makes it: a standard module, where `Me` is not valid.|

Excel workbooks and worksheets, Word documents, and Access forms and reports are supported.

## Notes

A document module of a supported host is code that presumes the host, which RD-VBA does not provide: see
[**RDC01005** Hosted document code](rdc01005.md) for moving it.
