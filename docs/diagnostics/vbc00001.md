# VBC00001 — Syntax error

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (parser / concrete syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBSyntaxErrorInfo`](../api/RDCore.SDK.Model.Errors.VBSyntaxErrorInfo.html)

A token was reached that the RD-VBA grammar cannot place in the current context. This is the parser's
**general fallback**: when the input cannot be parsed and no more specific code applies, it reports
`VBC00001`. Recurring shapes of syntax error are promoted from `VBC00001` to their own code in the
`VBC00042`–`VBC00999` range.

The diagnostic's verbose detail carries the parser's account of the failure: the token it found and
what it expected in its place. A client marks the reported range and reads the verbose
detail for the specifics.

## How it is raised

|Situation|What the verbose detail says|Resolution|
|---|---|---|
|A keyword, operator, or delimiter appears where the grammar expects something else, e.g. a misplaced `Then`, a doubled operator, an unbalanced bracket.|`expecting <token>, found <token>`|Put the tokens in a legal order.|
|A construct RD-VBA does not accept in this position, e.g. a declaration inside a procedure body, an expression used as a statement, or a `ByVal` before an argument of a `RaiseEvent` (**MS-VBAL §5.4.2.20** gives the statement no `ByVal`, and **§5.6.13.1** allows one only in the invocation of an external procedure; for any other call, see [VBC09327](vbc09327.md)).|the offending token and the rule that rejected it|Move or remove the construct.|
|A conditional-compilation directive line that is not well formed, e.g. `#If VBA7` with no `Then`, `#End If junk`, `#Iff X Then`, `#Const X As Long = 1`. The line is no directive, and opens, continues or ends no block ([**RD-VBAL §2.6.1**](../specs/rd-vbal.2.6.1.syntax-errors.md#directives-that-are-wrong)).|MS-VBA's message: `Expected: Then`, `Expected: expression`, `Expected: end of statement`, `Expected: =`, `Expected: identifier`, or `Expected: If or Else or ElseIf or End or EndIf or Const`, at the token MS-VBA puts the caret on|Complete or correct the directive; write a comment after it with `'`.|
|A conditional-compilation directive (`#If` / `#Else` / `#End If`) splits a single statement across branches, e.g. a procedure header whose return type differs per branch. RD-VBA, like the legacy Rubberduck parser, does not parse this.|the token after the directive that could not be joined to the statement|Rewrite so each branch holds whole statements: duplicate the header in each branch, or move the `#If` inside the body.|
|A stray or unterminated token, e.g. an unclosed string, an unexpected line continuation, a character outside any token.|the unexpected character or the unterminated token|Remove or complete the token.|
|`Debug` is used other than as `Debug.Print` or `Debug.Assert`, e.g. `Set Debug = Nothing`, `x = Debug`, `With Debug`, `Call Debug.Print("x")`. `Debug` belongs to the host, and is only ever written as those two statements.|`Debug`|Write `Debug.Print …` or `Debug.Assert …` as a statement of its own.|

## Notes

The RD-VBA grammar is permissive at the token level by design, and defers meaning to the semantic
layers. A `VBC00001` is therefore always a *structural* problem: the text could not be assembled into a
syntax tree at all.

Conditions that need symbol information (an undefined name, a duplicate declaration) are **not** syntax
errors. They are reported later, as
[semantic compilation errors](../specs/rd-vbal.2.6.2.semantic-compilation-errors.md).
