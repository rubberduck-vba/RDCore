# RDC01001: Use meaningful identifier names

**Severity:** Information &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `UseMeaningfulIdentifierNamesAnalyzer`

A name does not say what it names.

A name is reported when it breaks one of the rules of Rubberduck's *meaningful names* inspection, the first it breaks being the one that is told:

|Rule|Example|
|---|---|
|It has fewer than 3 characters.|`x`, `ws`|
|It ends with a digit: it says it is one of several, and not what makes it different from the others.|`total1`, `Sheet2`|
|It has no vowel, and is unlikely to be a word. A vowel is an `a`, `e`, `i`, `o` or `u`, accented or not.|`tmp`, `cnt`|
|It has no consonant: no letter other than a vowel.|`Oui`, `Aie`|

The names it applies to are the ones the module **chooses**: the module's own name (its `Attribute VB_Name`), variables, constants, parameters, procedures, properties, events, enumerations and their members, user-defined types and their
fields, and line labels. A line number is a number, and is not reported. A procedure of an external library is named by the library. A procedure that
implements an interface member, handles an event or is a lifecycle handler (`Class_Initialize`) is named by the interface, the event or the language, and is not reported; neither are the parameters of a handler, which the event names
(`ByVal X As Single`). A procedure with an underscore in its name that is none of these, such as `Test_1`, is reported like any other.
The accessors of a property are one name. The diagnostic is an opinion of the analyzer and not a condition of the language.

## Approving a name

A name that breaks a rule and that is fine - the counter of a loop is `i` - is approved by listing it, in the `Configuration:Diagnostics` section of the extension's
`appsettings.json`. A name is compared without regard to case, like every identifier of the language, and nothing is approved by default.

```json
{
  "Configuration": {
    "Diagnostics": {
      "MeaningfulNames": {
        "AllowedNames": [ "i", "j", "k", "x", "y" ]
      }
    }
  }
}
```

The list is `DiagnosticsOptions.MeaningfulNames`. It is a suggestion because renaming does not change what the declaration is.

## Fixing it

The diagnostic is fixed by renaming the declaration, which renames every name that refers to it ([`textDocument/rename`](../specs/rd-vbal.2.0.2.client-server-capabilities.md#textdocumentrename-and-textdocumentpreparerename)). Its code action is a rename to a name the user chooses: only the user can say what the name means. The module's own name has no code action: a module is renamed where the
project names it.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A name chosen by the module breaks a rule and is not approved.|`Dim tmp As Long`|Give it a name that says what it is: `Dim remainder As Long`; or approve it.|
|The module's own name breaks a rule.|`Attribute VB_Name = "Module1"`, `"Class1"`, `"UserForm1"`|Rename the module, in the project; or approve the name.|
