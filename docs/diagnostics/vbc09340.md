# VBC09340 — Expected Function or variable

**Severity:** Error &nbsp;·&nbsp; **Family:** `VBC` (static semantics / abstract syntax tree) &nbsp;·&nbsp;
**Source metadata:** [`VBCompileErrorInfo`](../api/RDCore.SDK.Model.Errors.VBCompileErrorInfo.html)

A subroutine is used where a value is expected.

A `Sub` does something and returns nothing: it can be called, but it has no value to print, to assign, or to give to an operator or to another procedure.

MS-VBA reports the same error, with the same message (recorded in Excel).

This code is raised by [`ObjectValueStaticSemantics`](../api/RDCore.SDK.Semantics.Static.ObjectValueStaticSemantics.html), and by
[`StatementStaticSemanticsEvaluator`](../api/RDCore.SDK.Semantics.Static.StatementStaticSemanticsEvaluator.html) for the target of an assignment.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A `Sub` printed or assigned.|`x = Module1.Reset`|Make it a `Function` that returns a value, or call it on a line of its own.|
|A `Sub` used as an operand.|`x = c.Increment + 1`|Call the `Sub` first, then read the value it changed.|
|A `Sub` of an object, or of a module named through it, assigned to.|`c.Remove(1) = 5`, `Err.Clear = 1`|Call the `Sub`, then assign what you meant to assign.|
