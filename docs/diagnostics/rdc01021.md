# RDC01021: Unassigned variable usage

**Severity:** Warning &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `UnassignedVariableUsageAnalyzer`

A local variable is read where nothing has assigned it, on any code path: the read always finds the default value of the variable's type.

A variable is created with the default value of its declared type: `0`, `""`, `False`, `Empty` or `Nothing` (**MS-VBAL §2.3** Variables).
A local variable of a procedure is created each time the procedure runs, so a read that no assignment reaches reads that value every time. The code
usually meant to assign the variable first.

What counts as an assignment is anything that may give the variable a value: an assignment, a `For` or `For Each` loop whose variable it is, `ReDim`, `Erase`,
`Input #`, a write to an element or a member of it, and passing it to a procedure that may assign it.

Not reported:

- an array, a user-defined type, and a variable declared `As New`: an element or a field is assigned on its own, and the first use of an `As New` variable
  creates its object;
- a read in the argument of `Len` or `LenB`, which asks for the size of the type;
- a variable declared `Static`, or in a `Static` procedure, which keeps its value from the previous call;
- a read that an assignment reaches on some code path and not on others.

The finding is the name of the variable where it is read.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A local variable is read before anything assigns it.|`Dim total As Long`<br>`Debug.Print total`|Assign the variable before it is read, or use the value it has: `Debug.Print 0`.|
|An assignment comes after the read.|`Dim name As String`<br>`MsgBox name`<br>`name = "Report"`|Move the assignment before the read.|
